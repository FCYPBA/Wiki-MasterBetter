# Wiki-MasterBetter — Developer Documentation

This is a plain-language, developer-facing version of the feature overview found in the [`wiki-masterbetter.me.js`](./wiki-masterbetter.me.js)
source file (the big comment block near the top of the file, just under the Tampermonkey header). That block is the
project's source of truth — every entry below keeps the same `Rule N` / `Feature XYZ` label used there and in the file,
so you can search the source for that exact label to find the matching implementation and its own, more detailed
comment.

The list below is **not reordered** — it stays in the order features were originally introduced, matching the source
file's own rule.

## A map of the site's pages

A few page routes on [wiki-masters.com](https://www.wiki-masters.com) come up repeatedly below:

| Route                 | What it is                                                        |
| --------------------- | ----------------------------------------------------------------- |
| `/marketplace`        | The marketplace home page, where cards are listed for auction     |
| `/marketplace/{id}`   | A single card's bidding ("auction") page                          |
| `/profile`            | Your own profile page                                             |
| `/profile/{username}` | Someone else's profile page                                       |
| `/pulls`              | The page where you open your card packs                           |
| `/collection`         | Your personal card collection                                     |
| `/global-collection`  | The "wishlist" view, where you can browse friends' wishlist cards |
| `/trades`             | Your trade history with other users                               |
| `/friends`            | Your friends list                                                 |

## Rules and Features

- **Rule 1a — Bigger notifications list.** Makes the notifications panel larger, so more notifications fit on screen at once without extra scrolling.
- **Rule 1b — Declutter auction pages.** On auction pages (`/marketplace/{UUID}`), hides the non-essential round buttons next to the card (wishlist and market analysis buttons). Applied once the page has finished rendering, and again when navigating to an auction page without a reload.
- **Rule 2 — Smarter "mark as read".** Clicking a notification also marks every notification older than it as read, not just the one you clicked.
- **Rule 3 — Descriptive tab title.** Adds useful context to the browser tab's title depending on what you're looking at — for example the card currently being bid on, or the username of the profile you're viewing.
- **Rule 4 — 3-column friends grid.** Rearranges your friends list into a tidy 3-column grid instead of one long single-column list.
- **Rule 5 — Compact friend action buttons.** Shrinks the "Message" and "Trade" buttons on the friends grid down to just their icon, to save space. The "Message" button of the trades shown in the "Envoyées" and "Historique" tabs of `/trades` is shortened the same way.
- **Rule 6 — Collapsible navigation bar.** The sidebar navigation collapses into icons by default and smoothly expands when you hover over it.
- **Feature NPN — Pin the navigation bar.** Adds a pin button so the sidebar can be kept permanently expanded instead of only expanding on hover. (This feature replaced the original Rule 8 — see below.)
- **Rule 7 — Click the first notification to clear all.** Clicking the very top (most recent) notification marks the entire notifications list as read.
- _Rule 8 no longer exists as its own item — it was folded into Feature NPN (the pinnable navigation bar) above._
- **Rule 9 — Auto-open "My Bids".** Arriving on the marketplace automatically switches you to the "My Bids" tab instead of leaving you on the default one.
- **Feature TBC — Quick action button on collection cards.** Adds a small button directly on each card in your collection that opens its sale/estimate modal in one click, instead of needing to open the card's modal yourself first. Feature EBC's bulk evaluation tools click through this same button automatically.
- **Rule 10 — Live notification counter.** Clicking a notification immediately updates the unread-count badge to match, instead of waiting for a refresh.
- **Rule 11 — Dim the "buy packs" banner.** Once you have zero packs left to open, the site's promotional banner encouraging you to get more is faded down instead of staying at full visibility.
- **Rule 12 — Clearer profile action buttons.** Improves the visibility/contrast of the action buttons shown on user profile pages, which all turn a muted green when hovered instead of the site's red (the "Suivi" button of a followed player stays red). On your own profile page, also caps the width of the tag-count list so it doesn't stretch the full width of the page, and keeps the tag names from being clipped at the bottom (descenders of letters like Q, G or g).
- **Feature PNP — Pack pile-up notifications.** Sends a browser push notification when you're accumulating a lot of unopened card packs, as a reminder to go open them.
- **Rule 13 — Trim long, fully-read notification lists.** Once every notification has been read, only the 20 most recent are shown at first; scrolling to the bottom loads the rest.
- **Feature TMB — Group bids by status.** Adds a toggle that splits your "My Bids" list into two groups: bids where someone has outbid you, and bids where you're still in the lead.
- **Feature CME — Close modals with Escape.** Lets you press the Escape key to close any open popup/modal, instead of having to find and click a close button.
- **Feature PNB — Bid-ending push alert.** Sends a browser push notification when one of your bids is about to end (30 seconds left), so you don't miss the chance to raise it.
- **Feature CAR — Claim all rewards at once.** Adds a "claim all" button on the achievements page that adds up and collects every pending reward in a single click, instead of one by one.
- **Feature AKP — Keyboard control on /pulls.** Lets you use the keyboard while opening packs: the arrow keys move between the pulled cards, Up/Down arrows jump straight to the first/last one, Space opens or closes a pack, E opens the currently selected card's full-size modal, and V does the same as E and then also puts that card up for sale. While a card is shown large, a small legend in the space to its left reminds you of the arrow shortcuts.
- **Feature SAT — Select all untagged cards.** Adds a "select all except tagged" button next to the site's own "select all" button on your collection page, so you can quickly select only the cards you haven't tagged yet.
- **Feature LBD — Enter key starts a bid.** On your collection page, typing an amount into the quick-bid field and pressing Enter starts the auction immediately, without needing to click a separate button.
- **Rule 14 — Clearer wishlist auction notifications.** Rewrites the wording of notifications about auctions for cards on your wishlist so they read more clearly, wrapping the card's name in guillemets and tinting "mise en vente" pink.
- **Rule 15 — Relabel the back button.** On a card's bidding page, renames the back button to a clearer French label ("Retour en arrière") instead of the site's default wording.
- **Feature PLB — (Obsolete) Quick profile links on bid pages.** Used to add a small "@" link right after each bidder's name (and the seller's name) on a card's bidding page. No longer in use: its code has been removed, and its number is kept only so the numbering of the other rules/features stays stable.
- **Rule 16 — Auto-scroll to your last unread notification.** Opening the notifications panel scrolls it straight down to your most recent unread notification, instead of starting at the top of the list.
- **Feature BSP — Track and grade sale prices.** Remembers how much each card has previously sold for (stored in your browser, not on the server) and uses that history to flag whether the current asking price looks like a good deal — or, on a sale you make yourself, how good that sale was. The top "legendary price" tier additionally requires the price to be at least 50 below the reference average. Unsold ("Non vendue") auctions are recorded too, except your own auctions, which are never recorded whatever their outcome (nor are cancelled ones). Every price it has recorded is listed in a table on your own profile page, along with export/import buttons — export downloads a CSV file and import reads one back — so you can carry that history over to another browser or device. The export also carries the list of players you follow (Feature FOL) the cards' saved rarities and tags (see Feature EVL); importing merges the followed players into your current list instead of replacing it. Those export/import buttons exist on the profile page only once some prices were observed, so the "Estimations" drawer of Feature EVL offers the same two buttons (⬇ / ⬆), available on `/collection` even on a brand-new browser. Every sold price is kept (there is no per-card cap), and the reference price a current price is compared with is the average of a card's stored prices once its single highest and single lowest price are left out (with fewer than 3 prices, all of them are averaged).
- **Rule 17 — Reposition "mark all as read".** Moves the "mark all as read" notifications button to the left side of the notifications panel, instead of wherever the site puts it by default.
- **Rule 18 — Auto-focus useful inputs.** Opening a card's modal automatically puts your cursor in its filter field (on `/collection` and `/pulls`), which opens its dropdown. Arriving on `/collection` also automatically focuses the search field (Rule 18b). Each can be toggled separately in the settings.
- **Feature ETS — Remember market value estimates.** Saves each card's estimated market value (seen on `/pulls` and `/collection`) in your browser, then displays that saved value next to the card's rarity tag on your collection page, so you don't have to look it up again.
- **Feature FCP — Toggle individual features.** Adds a settings button, next to the navbar's pin button, that lets you turn each feature of this script on or off individually; your choices are saved and take effect the next time the page loads.
- **Rule 19 — Cleaner notification text.** Rewrites notification wording in one single, consistent pass rather than several separate small tweaks.
- **Feature EBC — Bulk-evaluate your collection.** Adds buttons on `/collection` to estimate the market value of every card at once (or only the ones still missing an estimate), with a stop button to cancel partway through, plus a button to sort the whole page by estimated value from most to least expensive. Keeps the site's own rarity filter buttons grouped ahead of these new ones whenever the site re-adds them. A fourth, dark red "Estimation complète" button repeats the "missing estimate" pass across every page of your collection automatically, advancing the pager itself between pages; its label shows a minimum duration in minutes (one minute per page left, current page included, read from the site's "Page X / Y" indicator); the same stop button cancels it at any point. Keep the tab running the evaluation active and the browser window un-minimized for the whole run — background tabs and minimized windows get their timers throttled by the browser, which this feature's polling relies on, so a run left in the background is liable to stall or slow individual cards down. A card is never skipped for a slow market response: if its estimate hasn't arrived after a few seconds, its modal is closed and re-opened, as many times as needed, until the value is recorded (or you press the stop button). **Rate limit:** when the site's API refuses requests because they come too fast (HTTP 403 with the code `automation_limit`), the run pauses a few seconds (5 s, then 10 s, 20 s… up to 60 s while the refusals keep coming; the button shows a countdown), then retries the same card and continues at a slower pace (a growing pause after every card, which relaxes again after a streak of successes). A card still refused after its retry is not estimated: the script remembers it in your browser, under the cache key `wm-eval-limited-{card name}` (not part of the cache export), and the "missing estimate" passes (including "Estimation complète") leave it alone for 15 minutes. A "Réessayer les cartes limitées (N)" button, shown at the end of the filter bar only when the current page has such cards, re-estimates just those, whatever the age of their mark; a successful estimate removes the mark.
- **Rule 20 — Tag list follows keyboard selection.** Inside a card's modal (on `/collection` and `/pulls`), the tag list automatically scrolls to keep whichever tag you've highlighted with the keyboard in view.
- **Feature GCP — Click a friend's name to see their profile.** On the global collection/wishlist page, clicking the username of a friend who owns a card takes you straight to that friend's profile.
- **Rule 21 — Hide the legal disclaimer in the card modal.** Removes the small legal-notice text from a card's modal (on `/collection` and `/pulls`) to leave more room for the actual card details.
- **Rule 22 — Centered loading spinner and error message.** Centers the loading spinner on every page; on a card's bidding page, it also rewrites and centers the "Auction not found" message.
- **Rule 23 — Custom favicon.** Replaces the site's browser-tab icon with the Wiki-MasterBetter logo.
- **Feature FIS — Fix a page-transition visual glitch.** Corrects a styling issue with the loading spinner that shows up briefly during page transitions (on `/pulls`, `/friends`, `/guild`, `/achievements` and `/profile`).
- **Feature TUT — Built-in feature tutorials.** Adds a "❓" button next to the settings button that opens a modal with short explanations for the script's less obvious features.
- **Rule 24 — Bigger tag list.** Enlarges the tag list on your collection page. Sorting it is a separate option (Rule 24b).
- **Rule 25 — Clean up your wishlist.** Adds a button that removes every card you already own from your wishlist, all in one click.
- **Feature CNC — Copy a card's name.** Adds a small clipboard-copy button next to a card's name wherever that name appears: in the card modal, the auction modal, and a card's bidding page.
- **Rule 26 — Two-column trade history.** Displays your trade history as two flexible columns instead of one long single list, so more of it fits on screen.
- **Rule 27 — Filter trade history by partner.** Adds a search field above your trade history to filter it down to trades with one specific person.
- **Rule 28 — Clear button in the collection search field.** Adds a small "✕" button inside the collection search field to instantly empty it.
- **Feature OWL — Jump straight to a pulled card's Wikipedia page.** While opening packs on `/pulls`, pressing the W key opens the revealed card's Wikipedia page directly, without you needing to first open the card's modal and find the link yourself. (Feature AKP's own on-screen legend documents the shortcut.)
- **Rule 29 — Automatic page reloads when stuck.** On `/pulls`, once your pack pile has reached the maximum size, the page reloads every 10 minutes for as long as it stays full — opening packs cancels the timer instead of letting it reload mid-session. On a card's bidding page, if Rule 22's "Auction not found" message is showing, the page reloads itself once automatically, shortly after. On `/collection`, the page likewise reloads itself once when the site shows a red "a échoué" (failed) message.
- **Rule 30 — Bigger, reorganized bulk-tagging modal.** Widens the "apply a tag" / "remove a tag" modal on your collection page and lays its tag list out as a wrapping grid instead of one narrow column, so more tags fit on screen at once. On the removal variant specifically, the list is also sorted so the tags affecting the most of your selected cards appear first.
- **Rule 31 — Filter notifications by type.** Adds toggle buttons to the notifications panel's header — one each for sold cards, bought cards, bidding-related notifications (outbid refunds and unsold "returned to you" cards), and wishlist listings — that show only notifications of that type and hide the rest. Only one filter can be active at a time; pressing the active button again clears it. The chosen filter is remembered between visits.
- **Rule 32 — Red glow on an almost-finished auction.** On a card's bidding page, the "Se termine dans…" countdown glows red, the same pulsing effect Feature BSP gives a legendary price (in gold), once less than 10 seconds remain.
- **Rule 33 — Warn when you're already the highest bidder.** On a card's bidding page, the "place a bid" button turns light red when the current highest bidder is you, as a reminder you don't need to bid again.
- **Rule 34 — Keyboard navigation in the tag filter list.** Opening the tag filter popover on your collection page now moves focus straight into the list (onto the currently selected tag, or the first one), so arrow keys navigate it immediately instead of scrolling the page. Home/End jump to the first/last tag, and typing a few letters jumps to the next matching tag by name (ignoring its leading "#" and usage count).
- **Rule 35 — Your biggest card estimates.** Adds a "Top 40" button right after the page heading on `/collection` that opens a modal listing the 40 highest card estimates saved in your cache (Feature ETS), most valuable first, in three columns. Each entry has a "✕" button that deletes that estimate from the cache and grays the entry out, just like the cache entries on `/profile`. The modal fades in smoothly, and the single highest estimate is showcased above the grid with a golden pulsating glow. Cards whose estimate is still unknown ("?") are left out.
- **Rule 36 — Jump to any collection page.** On `/collection`, once the catalog has finished loading, the "Page X / Y" indicator becomes clickable: clicking it swaps it for a number field (1 to the last page). Press Enter to go to that page — the script presses the site's own previous/next buttons for you, one page at a time — or Escape (or click elsewhere) to cancel.
- **Feature BBS — Remember your biggest sales and purchases.** When you open the page of one of your own auctions that has sold, or one that you won, the trade (card name and final price) is saved in your browser, under the cache keys `wm-observed-best-sells` and `wm-observed-best-buys` respectively. Only your 40 biggest of each are kept (the same size as the "Top 40" estimates list), sorted from biggest to smallest; once full, a new trade only gets in if it beats the smallest one saved. Each price is saved with a short identifier taken from the auction's address (like Feature BSP does), so revisiting the same auction never records it twice. Each trade also stores its cutoff from the card's estimated market value (saved by Feature ETS): how far the price sits above or below it, in whole percent. It is shown as a badge such as "+223%" or "-21%" on the top edge of the trade in the profile modal (hover it for an explanation); trades whose card has no known estimate have no badge. Trades are listed by price by default; a "Trier par bonne affaire" switch in each modal (off until you turn it on, and remembered afterwards) re-orders them by how good a deal they were. The score weighs how far the price sits on the right side of the card's estimate (the premium for a sale, the discount for a purchase) by the logarithm of that estimate, to the 4th power (edge × ln(1 + estimate)⁴), so a 971 sold at +175% scores well above a 250 sold at +216%, and a 605 bought at -64% well above a 13 bought at -93% (trades without an estimate last). Each entry in those modals also exposes its score as a `data-score` attribute (rounded to 2 decimals; absent when the card has no estimate). Already-saved trades get their cutoff filled in or updated automatically. The auctions listed in the "Historique" tab (sales) and the "Gagnées" tab (purchases) of `/marketplace` are picked up the same way, so you don't have to open each one yourself. On your own profile, "Mes plus grosses ventes" and "Mes plus gros achats" buttons between "Ma Collection" and "Mes Amis" open a modal listing those trades, in the same layout as the "Top 40" estimates (biggest one showcased with a golden glow, "✕" to delete a trade from the cache).
- **Feature FOL — Follow players.** On another player's profile, an eye button next to the "Signaler" button, at the top right of the profile card, lets you follow them (it reads "Suivre", then turns red and reads "Suivi" while they are followed; click again to unfollow). The list of followed players is kept in your browser, under the cache key `wm-followed-users`. On a card's bidding page, a small red eye is then shown right after the name of every followed player: the seller, the bidders and the current highest bidder. On your own profile, the players you follow are listed under the sold-prices block, alphabetically, each linking to their profile, with a "✕" to unfollow them. That list is part of the sold-prices block's export/import (see Feature BSP).
- **Rule 37 — Hide the "favorite" bulk buttons.** On `/collection`, the bulk-action bar that appears at the bottom of the page when you select cards no longer shows its "add to favorites" and "remove from favorites" buttons, leaving only the tagging and discard actions.
- **Rule 38 — Highlight cards without an estimate.** On `/collection`, adds a "Sans estimation" toggle right after the "Top 40" button. While on, every card of the page that has no saved estimate (Feature ETS) gets a light red halo; a card whose estimate is "?" counts as estimated and is left alone. The toggle state is remembered between visits, under the cache key `wm-no-eval-halo`.
- **Feature UDS — Personal descriptions for other players.** On another player's profile, a "Description" button (pencil icon) is added at the top right, right before the "Suivre" button. It opens a small modal with a text field where you can note what that player is after, what they offer, etc.: fewer than 128 characters, with a live counter, on a single line. Press Enter or "Enregistrer" to save (saving an empty text deletes the description); Escape, a click outside or the "✕" close the modal. The description is kept in your browser under the cache key `desc-{username}`, and is displayed, muted and in full, right after the player's name on their profile and on `/friends` (wrapping below the name when there is no room beside it).
- **Rule 39 — Progress bars pinned in the achievement cards.** On `/achievements`, the script looks every 10 seconds for the achievements' progress bars (they appear once the list has loaded). As soon as it finds some, it moves all of them to the bottom right of their card, at half the card's width, without extra margins.
- **Rule 40 — Wider tag manager modal.** The "Gérer les étiquettes" modal (create, rename, recolor or delete your tags) now takes up to 90% of the screen width instead of a narrow column, so very long tag names are easy to read and edit.
- **Rule 41 — Dim the cards you already own.** On `/marketplace` and `/global-collection`, every card that carries the "Possédée" tag is shown with low visibility so your eyes go to the cards you don't have yet. Hovering a dimmed card brings it back to full opacity. On `/marketplace` the dimming only applies to the "Parcourir" tab (not "Mes ventes", "Mes enchères", "Gagnées", "Historique" nor "Suivi"), and a switch of Feature MLM's bar turns it off and on (remembered in `localStorage` under `wm-owned-dim`, on by default). The rule itself is still enabled or disabled from the features configuration; disabled, the switch is not shown.
- **Feature GLM — Shield icon for your guild members.** Opening the "Membres" tab of `/guild` makes the script remember who is in your guild (the list is loaded 50 members at a time, so the script clicks the "Afficher plus" button by itself until everyone is displayed; then the saved list is replaced by exactly those, so people who left disappear). A small blue shield is then shown right after a member's name wherever it appears on its own (profiles, trades history, friends, bidding pages, global collection...); names inside a sentence, like notifications, are not decorated. On the guild's own member list there is no shield: the personal description is shown under each member's name instead. Elsewhere, hovering the name or the shield shows the personal description you wrote for them (Feature UDS), or "Membre de la guilde" when there is none. The list is kept in your browser under the cache key `wm-guild-members` and is not part of the cache export.
- **Rule 42 — Estimated total of a received trade's cards.** In the "Reçues" tab of `/trades`, each side of a trade (what the partner offers, and what they want in exchange) gets a line under its heading with the sum of its cards' estimates (Feature ETS), the number of cards, and how many of them have no known estimate (those count for nothing in the sum), e.g. "≈ 1 240 · 8 cartes · 2 sans estimation".
- **Feature MTG — Mass-tag your collection from search terms.** In the "Gérer les étiquettes" modal, every tag gets a field where you list search terms separated by commas (e.g. "louvre, versailles"); they are kept in your browser under the cache key `tag-terms-{tag name}`, and follow the tag if you rename it. On `/collection`, an "Étiquetage en masse 🏷️" button is added at the end of the filter bar. A small modal first lists every tag that has terms, each with a checkbox (all checked) so you can run only some of them ("Tout cocher / décocher" flips them all, "Lancer (N)" starts the run, Escape or "✕" cancels). Rows are compact (drag handle, rank, checkbox, tag name, and a "N termes" count whose tooltip lists the terms) and can be dragged and dropped to choose the order in which tags are processed, which decides which tag wins when a card matches several of them (e.g. put "Oiseau" before "Espèce" so a bird species gets "Oiseau"); that order is remembered between runs, under the cache key `tag-run-order`, and a renamed tag keeps its place. It then sets the site's tag filter to "Sans étiquette", then for each tag and each term types the term in the search field, selects every card of the results (select mode), and applies the tag through the bulk "Étiqueter" button. Tagged cards leave the filtered view, so the script stays on the first page and repeats until nothing is left for that term; the filter is reset to "Toutes les étiquettes" at the end. Only cards without any tag are ever touched, so a card matching several tags keeps the first one it got (tags are processed in the order you set in the picker, then term by term). To use your terms on another computer (same account, so the tags exist there too), the "Gérer les étiquettes" modal has "⬇ Exporter les termes" and "⬆ Importer des termes" links under its title: the first saves every tag's terms and the processing order to a JSON file (`wmb-etiquetage-en-masse.json`), the second loads such a file, replacing the terms of the tags it contains (other tags are left alone) and applying its order. The same button stops the run at any point. When the run ends (completed, stopped or failed), a recap panel docked on the right lists, tag by tag, every card that was tagged, as a grid of portraits with their names and counts. It leaves the page behind usable, so you can review several cards in a row: clicking a portrait types that card's name in the search field, which brings it up in the grid so you can open it and re-tag it. Only its "✕" closes it. The site's search also matches categories, not only titles, so choose terms carefully. As with Feature EBC, keep the tab active and the window un-minimized for the whole run. The run is traced in the browser console (lines starting with `[WMB-MTG]`) and any failure is reported in an alert listing what the script found on the page.
- **Feature CCL — Copy a card as an image.** Hovering any card (collection, pulls, marketplace, modals…) shows a small 📷 button at the top center of that card. Clicking it copies the card as a PNG image (illustration, text, stats) into the clipboard, ready to be pasted in a chat; the icon turns into ⏳ while rendering, then ✅ (or ❌ on failure). It relies on the html-to-image library, loaded through the script header's `@require`.
- **Rule 24b — Sort the tag list by usage.** Option complementing Rule 24: on your collection page, sorts the tag list by how many cards carry each tag, from most used to least used. Can be disabled on its own in the settings to keep the site's default order while the list stays enlarged.
- **Feature EVL — "Estimations" drawer on the collection.** On `/collection` (desktop widths only), a thin gutter with a list icon and the vertical label "Estimations" sits between the left menu and the page. Clicking it slides open a panel from the left, which pushes the collection to the right instead of covering it; the open/closed state is remembered between visits, under the cache key `wm-estimations-drawer-open`. The panel lists every card whose estimate is saved in your browser (Feature ETS; the "?" ones are left out), from the most to the least expensive, 100 per page: rank, card name, rarity and estimate, with a pager (first / previous / next / last page and a "Page X / Y" indicator) at the bottom. Each row has a 🔍 button that types the card's name in the collection's search field, so you don't have to copy and paste it (the row stays highlighted; the site's other filters, such as the tag filter, still apply). Card names (and their rarity) are tinted with their rarity's own colour, the one the site uses in its collection, and a row of rarity buttons (L, UR, SR, R, PC, C, in the site's own colours) under the header filters the list down to one rarity: click the same button again to show everything. A card whose rarity isn't known yet has no tint and is hidden while a filter is active. A 🗑 button on each row removes that card from the cache, for a card you sold or traded: its saved estimate and rarity are deleted, the row leaves the list, and the estimate shown on the card's rarity tag in the collection is taken off. A bar under the header then offers an "Annuler" button to put the last removed card back (until you remove another one or close the panel). The header's ↻ button refreshes the list, which otherwise reflects your saved estimates at the time you open the panel or change page, its ⬇ and ⬆ export and import the whole script cache as CSV (estimates, saved rarities, observed sale prices, followed players — the same file as the export on the profile page), so the estimates do not have to be recomputed on a new browser or computer (the page reloads after an import), and its ✕ closes the panel. A second bar filters by your tags (étiquettes): chips for "Sans étiquette" and every tag, with the number of estimated cards carrying it, and two modes — "Exclure" hides the cards carrying any selected tag (to find what is free to sell, i.e. not in a category you keep), "Garder seulement" shows only those. The selection and the mode are remembered. A card's tags are saved, like its rarity, whenever the card is displayed on `/collection` (under `wm-tags-{card name}`, refreshed each time, so re-tagging is picked up); a card whose tags were never seen is hidden by any active tag filter (it could be in a category you keep) and the bar says how many there are. Hovering a card's name in the list shows its tags. The rarity column is filled from what the script has seen of your collection: whenever a card that has an estimate is displayed on `/collection`, its rarity is saved in your browser under the cache key `wm-rarity-{card name}` (part of the cache export); until then the column stays empty for that card. Fill the list by running Feature EBC's bulk evaluation, whose "Estimation complète" also goes through every page of your collection and so records every rarity.
- **Feature AAR — Live archive of auctions matching search terms.** A "📦" button, in the row of buttons at the top of the left menu (right after the "❓" one), opens a modal where you list search terms separated by commas (e.g. "avion, bateau"; kept in your browser under the cache key `wm-auction-archive-terms`). From then on, every 5 minutes, the script searches the marketplace for each term and archives every auction it finds (a "Légendaires" ribbon under the terms field has a checkbox that, once ticked, also archives every Legendary auction, with or without search terms: the script then also reads `/api/marketplace?...&sort=recent&rarity=L` like a term, the auctions it finds carrying the pseudo-term `rarity:L`; the choice is kept under the cache key `wm-auction-archive-legendary`), in your browser's IndexedDB (database `wmb-auction-archive`; far roomier than the other cache entries, which live in localStorage). The auction's identifier is the storage key, so an auction is stored once however many passes or terms find it. A regular pass costs one request per term (the search is read newest first and stops at the first page with nothing new); the first pass of a new term reads the whole list (up to 100 pages of 50). Once an auction is over (30 seconds after its end time, since the site settles it a few seconds later), the script fetches it once more to record its result: final price (empty when unsold), number of bids and number of different bidders; an auction whose end was pushed back is simply waited for again, one still "active" after its end is retried with a growing delay (then flagged `unresolved`), and one the site no longer knows ends as `not_found`. Each archived auction holds its identifier, the term(s) that found it, the card's name, rarity, shiny flag, language, attack/defense, quality score and page views, the seller, its starting price, its creation and end times, its status (`active`, `settled_sold`…) and, once over, the final price, the winner, the settlement time, the bid count and bidder count, the time of the first and last bid, and the full list of bids (amount, bidder and time of each, oldest first), which makes it possible to study last-minute bidding or who bids on what. Archives made before these details were kept are completed in the background (newest first, 60 auctions per pass, after the regular work); the modal says how many remain. The modal shows how many auctions are archived (and how many still wait for their result), the last and next pass times, a possible rate-limit pause and the last error, the space the site uses in your browser, and offers "Scanner maintenant" (starts a pass right away), "Exporter en CSV" (one flat line per auction, for a spreadsheet, with the time of the last bid and how many seconds before the end it came) / "Exporter en JSON" (every field, bids included; both are written page by page so a very large archive can be exported), "Importer (JSON)", "Compacter (> 30 j)" and "Vider l'archive". "Importer (JSON)" reads back a JSON export to move an archive to another browser or computer (the CSV cannot be imported); the file is read as a stream so a very large one is fine. Auctions are merged by identifier with what the archive already holds: an unknown auction is added, and for a known one the more complete version is kept (finished beats open; with its bids beats compacted, which beats a result still to fetch; the local one when equal) with the search terms of both united. Nothing is ever deleted by an import, and the result (added, updated, already up to date, ignored lines) is shown in a notification. Imported auctions still open are resolved by the collection like any other; the auction price history (Feature ACH) uses imported sales right away. Compacting is manual and cannot be undone: for auctions finished more than 30 days ago it deletes the detailed list of bids (and the internal bookkeeping fields and the seller/winner identifiers, the names being kept) and keeps every price, count, date and name, which roughly halves their size. As an order of magnitude, a full auction weighs about 1.2 KB, so 4000 auctions a day make about 1.7 GB a year (about 0.9 GB compacted); saving terms asks the browser to keep the archive persistently so it isn't evicted when the disk runs low. **A wiki-masters.com tab must stay open**: nothing is collected while the browser is closed, or if it discards the idle tab to save memory. With several tabs open, only one (the oldest) collects, and another takes over if it is closed. Reloading the page does not trigger an early pass. Like Feature EBC, the script handles the API's `automation_limit` rate limit: all requests are spaced by over a second, and when the site refuses them the collection pauses 1 minute, doubling up to 10 minutes while the refusals keep coming. The archive is not part of the cache export/import of `/profile`; it is exported and imported from its own modal only. The collection is traced in the browser console (lines starting with `[WMB-AAR]`). Clearing the site's data in your browser deletes the archive: export it first. The modal's status also lists, for each source (every term, and the Legendaries), the time of its last scan and how many auctions it saw and archived for the first time, or the HTTP error the site answered; the Legendaries are scanned last and capped at 20 pages per pass, and a source the site refuses doesn't stop the others. Discovering new auctions and fetching the results of finished ones are two independent loops (searches every 5 minutes, results every minute), so a failing, slow or rate-limited search never delays the results, nor the other way round; they share the request pacing and the rate-limit pause. The modal shows the last and next run of each.
- **Feature ACH — Card price history on its bid page.** On a bid page (`/marketplace/{UUID}`), a "Historique de la carte (archive)" block is added at the end of the column holding the card's name and the bid panel. It plots, from the auction archive (Feature AAR), the final price of every archived sale of the same card (same Wikipedia title, same shiny flag and same rarity, a card can exist in several; the auction on screen is left out): one dot per sale, a dashed median line and, from 4 sales, a smoothed trend line (Gaussian-weighted moving average; geometric on a logarithmic axis, which is used when prices span more than a factor 40; the line breaks where sales are too sparse). Hovering a dot shows its date and price. Under the chart: number of sales, share of auctions that sold, median and price range; with a single sale only that text is shown, and a card whose archived auctions were all unsold says so. Nothing is shown when the card was never archived, and nothing is requested while the archive is empty. The card is identified from the archive when this auction is in it, otherwise with one `GET /api/marketplace/{UUID}`. Read-only: it never writes to the archive nor starts the crawl. It needs the archive's `card` index, added by IndexedDB version 3: after updating the script, reload the other wiki-masters tabs so the upgrade is not blocked.
- **Feature CPR — Recap of the collection page, copyable as an image.** On `/collection`, a bar is added at the top of the block holding the pager and the cards grid. It gives the number of cards of the page on display, their total estimated value and, per rarity (L, UR, SR, R, PC, C, in the site's order and colours), the number of cards and their value. A card's value is its estimate (Feature ETS, the `eval-{name}` cache entry); cards with no estimate (or the "?" placeholder) add nothing to the sums and are counted apart ("sans estimation"), a rarity with no estimated card shows "—". Only the page on screen is counted, not the whole collection; the bar follows the page (page change, new estimates, filters, search) without any action. Two buttons on the bar render the recap and the cards of the page as an image with the `html-to-image` library (same as Feature CCL; the pager rows, the cards' quick-action buttons and the two buttons themselves are left out): "📷" copies it to the clipboard (to paste it in a chat), "💾" downloads it as a PNG named `{tag}_{search}_page-{n}_{date}.png`, where `{tag}` is the tag chosen in the collection's tag filter and `{search}` the text of the search field (each is left out, with its underscore, when empty; characters a file name can't hold are replaced by spaces and each part is cut at 40 characters), e.g. `Aero - Almanach_avion_page-1_2026-11-07.png`. A "Valeurs" checkbox next to the two buttons (checked by default, remembered in `localStorage` under `wm-cpr-include-values`) decides whether the recap's estimated values (the total, the "sans estimation" note and each rarity's value) are drawn in the image: unchecked, only the number of cards, in total and per rarity, remains; the bar on screen is not affected, and neither are the estimates shown on the cards themselves. The icon shows ⏳ while rendering, then ✅ or ❌. The image is drawn from the page's own content, so it takes a single click and no screen-capture permission; for the same reason it cannot start by itself (the clipboard needs a click). Wikipedia thumbnails are loaded with CORS: one that cannot be loaded is left blank in the image. Can be disabled from the features configuration. Errors are logged in the browser console (lines starting with `[WMB-CPR]`).
- **Feature MLM — Auction list: switches and archive median.** On the marketplace's auction list (`/marketplace`), a bar of compact switches sits in the page header, between the "Marché" title block and the "Sélectionner" button, and only on the "Parcourir" tab (on narrow screens it wraps under the title). Each switch is a short label plus a small version of the site's own settings switch; the explanation is in its tooltip. "Mise de départ" (remembered in `localStorage` under `wm-mlm-start-only`) hides the auctions that already have bids and keeps the cards that still show the "Mise de départ" label (a card with bids shows another label). "Atténuer possédées" turns Rule 41's dimming of the cards you own off and on (only shown while Rule 41 is enabled; `wm-owned-dim`, on by default). "Masquer possédées" (`wm-mlm-hide-owned`, off by default) removes the cards you own (the ones with the "Possédée" tag) from the view. A switch that hides cards shows how many next to its label. Hiding is a CSS class, never a removal, and the cards that "Charger la suite" adds are handled as they come. Each card also gets a last line "médiane {prix} · {n} ventes" (the tooltip gives the range): the median final price of that card's archived sales (Feature AAR) with the same name and the same rarity, shiny sales apart. A card that looks shiny (✨ or "shiny" in its text) gets no line, and neither does a card with no archived sale. Archive lookups are cached per card name for one minute. Can be disabled from the features configuration. Errors are logged in the browser console (lines starting with `[WMB-MLM]`).
- **Feature AWL — Auction watchlist.** On a bid page (`/marketplace/{UUID}`), a ☆ button is added at the start of the card's name heading (it reads ★ once the auction is watched; clicking again stops watching it). On the market page (`/marketplace`), a "Suivi" tab is added at the end of the tab bar ("Parcourir", "Mes ventes", "Mes enchères", "Gagnées", "Historique"). Its label shows how many watched auctions are still running ("Suivi (3)") and turns amber when one of them ends in less than 10 minutes. Selecting it shows, under the bar, the watched auctions: rarity badge in the site's colours, card name (✨ for a shiny one), current bid and number of bids (or the start bid when nobody has bid, or the final price once sold), and a live countdown. Running auctions come first, the soonest to end on top, then the finished ones, the latest first. Clicking a row opens the auction in a new browser tab, ✕ stops watching it, "Retirer les terminées" clears the finished ones, and "Actualiser" refreshes the data. The site's own tabs and content are not touched: while "Suivi" is selected they are only hidden, and clicking any of the site's tabs brings them back as they were. The data (`GET /api/marketplace/{id}`) is fetched when "Suivi" is selected (then every 2 minutes while it stays selected), when an auction is added, and once per page load when a watched auction's page is visited, through Feature AAR's paced request gate (same request budget, same rate-limit pause); nothing is fetched while the tab is not shown. The list is stored in `localStorage` under `wm-awl-items`, shared by all tabs, and finished auctions are dropped 14 days after their end. Can be disabled from the features configuration.
- **Feature ETA — Estimated end time of long auctions.** When an auction has 1h or more left, an estimated end time is shown next to its duration: "≈ 18:42" for today, "≈ demain 02:15" for tomorrow, "≈ sam. 02:15" within the week, with the date beyond (the tooltip gives the full date). On `/marketplace` (every tab) it is added under the "Durée" value of each card; on a bid page (`/marketplace/{UUID}`) it follows the countdown. The site only gives the time left to the minute, so the value is an estimate: it is computed once and kept steady while the countdown ticks, and only replaced when a fresh estimate differs by more than 2 minutes. It disappears when less than 1h is left or once the auction is finished. Nothing is fetched: it is computed from the text the site displays. Can be disabled from the features configuration.
